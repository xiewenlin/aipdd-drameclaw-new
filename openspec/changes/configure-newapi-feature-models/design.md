## Context

当前 CE 运行时以 `settings.db` 中的模型网关配置为主，但仍保留 official/custom 模式、前端 Provider 渠道管理、环境变量默认值、项目级图片 selection 和视频 backend，以及若干云 Provider 直连分支。文本模型已大量使用逻辑模型名，图片、视频、音频和 Embedding 的选择方式则各不相同。

目标用户拥有一个兼容 NewAPI/OpenAI 的服务地址和 API Key，希望配置页能够获取该地址暴露的模型，并将任意模型显式绑定到具体业务功能。`/models` 的标准响应通常不能可靠表达图片、视频或音频能力，因此类型识别不能成为选择限制，也不能触发未经用户确认的默认绑定。

## Goals / Non-Goals

**Goals:**

- 将自定义 NewAPI 设为唯一云端模型凭证和 API Base URL。
- 在配置页完成连接测试、模型同步、模型分类和功能绑定。
- 使用后端维护的功能目录覆盖文本、视觉文本、图片、视频、音频和 Embedding 功能。
- 所有项目严格使用同一套全局功能绑定，不允许请求或项目级模型覆盖。
- 模型类型只用于排序和筛选，任何已同步模型都可以手动绑定到任意功能。
- 未配置模型时快速失败并返回可定位到功能的错误，不做隐藏回退。
- 保留一个由服务端配置的“官方服务”外链，但完全移出运行时渠道逻辑。
- 为历史全局配置和项目配置提供可检查、可回滚的迁移路径。

**Non-Goals:**

- 不在本次改造中实现或托管 NewAPI 服务。
- 不保证仅根据模型名称准确判断模型能力。
- 不自动为用户购买、创建或配置上游 Provider 渠道。
- 不移除 ComfyUI 等明确的本地计算后端；本次只统一云端模型来源。
- 不在首版提供复杂的按成本、限额、延迟或自动故障转移路由。
- 不提供项目级或单次请求级模型选择；模型只能在全局配置页调整。

## Decisions

### 1. 单一自定义 NewAPI 连接取代 official/custom 模式

配置只保留规范化后的 `base_url`、受保护的 API Key、连接状态和最近测试时间。后端接受带或不带 `/v1` 的地址并生成唯一 API Base URL，禁止业务模块拼接第二个 `/v1`。

选择该方案是因为它与用户心智一致，且能移除官方凭证、Provider 渠道和业务运行时之间的多层耦合。备选方案是保留 official/custom 标签页，但会继续产生两套状态和回退语义，因此不采用。

### 2. 模型目录保存“上游事实”和“本地标注”

每次同步保存 `model_id`、原始元数据、`available`、`detected_capabilities`、`manual_capabilities`、`last_seen_at`。有效能力优先使用用户手动标注，否则使用自动推断；推断失败时为 `unknown`。

同步采用增量合并：新增模型进入目录，已有模型保留手动标注和功能绑定，消失模型标记不可用而不删除。这样可以解释失效绑定并避免一次短暂上游故障破坏配置。

能力使用集合而不是互斥单类型，例如模型可以同时是 `llm` 和 `vision_llm`。首版能力枚举为 `llm`、`vision_llm`、`image`、`video`、`audio`、`embedding`、`unknown`。

### 3. 后端维护功能目录，前端动态渲染

后端提供稳定的功能 ID、显示名称、能力推荐、是否必需和测试协议。首批功能至少包括：

- 文本：`hermes_llm`、`scene_builder_llm`、`content_rewriter_llm`、`video_prompt_optimizer_llm`
- 视觉文本：`vision_analysis_llm`
- 图片：`sketch_image`、`render_image`、`scene_master_image`、`scene_reverse_image`、`scene_360_image`、`prop_reference_image`
- 视频：`image_to_video`、`text_to_video`
- 音频：`character_tts`
- 向量：`knowledge_embedding`

前端不再单独硬编码功能模型清单。新增功能只需后端目录和对应运行适配器更新，前端按 API 数据展示。

### 4. 功能绑定是唯一的云模型选择语义

全局绑定以 `feature_id -> model_id | null` 保存。下拉框默认优先展示能力匹配且可用的模型，同时提供“全部模型”；`unknown` 模型不会自动选中，但可手动绑定。保存时对类型不匹配只警告、不阻止，因为上游可能使用自定义模型名。

系统不在首次同步后自动绑定。可以后续增加“生成推荐草稿”，但必须由用户确认后才能生效。

### 5. 统一 Runtime Resolver，保留协议适配器

运行时通过 `resolve(feature_id)` 获取唯一的全局功能绑定。解析结果包含 NewAPI Base URL、凭证引用、模型 ID、功能 ID 和协议适配器。请求 payload 和项目配置中的历史模型选择不得改变解析结果；迁移完成后应拒绝或忽略这些字段。不存在绑定、模型已失效或连接未配置时返回结构化错误。

文本、图片、视频、音频和 Embedding 仍需要不同的 HTTP 协议及任务轮询方式，因此保留现有协议适配器，但适配器不得读取 Provider Key、官方模式或独立 Base URL。模型名称不再包含 `newapi_` 传输前缀。

### 6. `/models` 同步与实际能力测试分离

连接测试只验证鉴权和 `/models` 可访问。模型类型推断是启发式结果，不声称模型可调用。配置页对已绑定功能提供最小能力测试，由对应适配器调用 NewAPI 的文本、图片、视频、音频或 Embedding 接口。

这样避免同步模型时产生费用，也避免把不完整的 `/models` 元数据当作能力证明。

### 7. 官方渠道变为服务端配置的普通链接

后端状态接口返回 `official_service_url`，首期配置为 `https://newapi.chonghuayunke.com`。前端使用“没有可用的 NewAPI 服务？获取官方服务”作为文案并在新窗口打开该链接，不发送凭证、不切换模式、不参与运行时解析。部署时仍允许通过 `OFFICIAL_MODEL_SERVICE_URL` 覆盖地址；URL 缺失时隐藏入口。

## Risks / Trade-offs

- [NewAPI 实现对图片和视频接口不一致] → 复用并收敛现有协议适配器，按功能测试；明确记录所支持的 NewAPI 协议版本。
- [模型名称推断错误] → 推断只用于推荐，允许多能力手工标注和“全部模型”强制选择。
- [历史项目仍保存旧模型字段] → dry-run 报告这些字段及其影响，备份后移除或停止读取，确保历史项目不能覆盖全局绑定。
- [同步时模型短暂消失] → 标记不可用而不删除；不自动清除绑定，运行前给出明确错误。
- [API Key 泄露] → 列表和读取 API 永不返回完整 Key，日志过滤 Authorization，请求更新时使用“留空表示不替换”。
- [关闭直连后部分能力暂时不可用] → 分能力切换并保留一个版本的兼容开关；只有通过对应冒烟测试后才关闭旧云端路径。
- [功能槽位过细导致配置负担] → 允许多个槽位绑定同一模型，并在 UI 提供批量应用，但不自动保存。

## Migration Plan

1. 增加新数据结构、功能目录和只读/写入 API，不改变旧运行时。
2. 上线新配置页和模型同步；允许用户完成连接与绑定并运行校验。
3. 增加 Resolver 和迁移观测逻辑：新运行时只读取全局绑定，旧字段仅用于生成迁移报告，不参与模型选择。
4. 提供 dry-run，列出全局逻辑模型、图片 selection、视频 backend、音频和 Embedding 的拟迁移结果及未识别项。
5. 用户确认后写入全局绑定，备份并移除历史项目模型选择字段，保存配置版本及迁移备份。
6. 按文本、图片、视频、音频、Embedding 顺序切换运行时，并完成每类冒烟测试。
7. 移除官方运行模式和云 Provider 直连 UI；保留官方外链和一个发布周期的只读兼容/回滚代码。
8. 稳定后删除旧凭证字段和直连云端分支。

回滚时恢复迁移前的 `settings.db`/配置备份，关闭新 Resolver 开关并重新启用旧读取路径；模型同步目录本身可以保留，因为不影响旧运行时。
