## Context

CE 的 NewAPI 连接和功能模型绑定保存在 `settings.db`，每次有效修改会递增 `runtimeRevision`。普通运行时 Resolver 按调用读取全局绑定，Hermes 也有工作进程指纹轮换，但 Cognee 依赖进程级环境变量、`cognee.config` 和第三方客户端缓存。当前实现通过 `_active_gateway_fingerprint` 检测变化，并要求重启后端。

Cognee 的配置是进程全局可变状态，因此不能在同一进程中让两套配置真正并行运行。直接在设置保存时覆盖环境变量，会让正在执行的知识库任务在多个 LLM/Embedding 请求之间切换配置。热更新必须以任务一致性优先，并接受切换时短暂排空。

## Goals / Non-Goals

**Goals:**

- 保存 NewAPI 地址、Key、知识库 LLM 或 Embedding 绑定后，无需重启后端。
- 单个 Cognee 操作从开始到结束只使用一个不可变运行时快照。
- 当前任务完成后，新任务自动使用最新有效配置。
- 支持连续配置更新、多进程部署、应用失败诊断和 Embedding 兼容性保护。
- 不在日志、状态接口或异常中泄露 API Key。

**Non-Goals:**

- 不允许项目级或请求级模型覆盖全局配置。
- 不让同一进程中的两代 Cognee 配置并行执行。
- 不自动重建所有历史知识库，也不自动删除旧向量数据。
- 不把模型列表同步当作模型能力验证，不在保存时自动产生计费请求。
- 不改变 EE 通过部署环境变量管理配置的规则。

## Decisions

### 1. 使用不可变运行时快照，而不是直接比较环境变量

新增 `ModelRuntimeSnapshot`，至少包含：`runtime_revision`、NewAPI Base URL、脱敏前的内存 Key、知识库 LLM 模型、Embedding 模型、Embedding 维度、是否发送维度参数，以及不包含明文 Key 的配置指纹。

协调器在每次 Cognee 任务入口读取最新数据库配置并构建快照。`runtimeRevision` 用于快速发现变化；有效 Cognee 指纹用于判断本次版本变化是否真的需要重配置。例如只修改图片模型时，协调器只推进已观察版本，不排空 Cognee。

不把 CE 数据库配置复制为长期部署配置；环境变量只作为 Cognee 第三方库兼容桥，并由协调器在受控切换区间统一更新。

### 2. 使用“代际租约 + 排空切换”保证任务一致性

每个进程维护一个异步协调器，状态为 `uninitialized`、`ready`、`draining`、`applying` 或 `failed`。所有会调用 Cognee 的公开操作必须在完整操作期间获取租约，而不是只在 `init_cognee()` 周围加锁。

- 当前快照与期望快照一致时，允许同代任务按现有并发限制执行。
- 发现有效配置变化时，停止发放旧代新租约并进入 `draining`。
- 已持有租约的任务继续使用旧代配置直至完成。
- 活跃租约归零后，在独占锁内应用最新快照，再向等待任务发放新代租约。
- 排空期间再次保存配置时，只保留最新期望快照，跳过中间版本。

选择排空而不是立即覆盖，是因为 Cognee 的环境变量和配置对象是进程全局状态；选择任务级租约而不是单次请求级锁，是为了避免一个导入任务在 `add`、`cognify` 和索引阶段之间切换模型。

### 3. 原子应用 Cognee 配置，并提供失败隔离

切换分为准备、应用、验证和提交四步：

1. 在修改全局状态前解析连接和两个知识库绑定，校验字段完整性与维度合法性。
2. 保存当前可恢复的 Cognee 配置值，在独占区间更新兼容环境变量、`cognee.config` setter 和内部客户端缓存。
3. 执行不产生上游费用的本地一致性检查，确认 LLM 与 Embedding 配置均指向同一快照。
4. 成功后提交活动快照和时间；失败则恢复旧进程状态，但将协调器置为 `failed`。

失败后，旧配置仅用于保持正在收尾的旧代任务稳定，不向新任务静默发放。新任务返回结构化 `model_runtime_reload_failed`，直到用户修正配置或下一次配置版本成功应用。

Key、Base URL 或绑定缺失属于有效但不可运行的新配置。旧代排空后，新任务返回现有的连接/绑定缺失错误，不继续偷偷使用旧 Key。

### 4. 通过适配层集中清理第三方缓存

把当前 `init_cognee()` 中分散的环境变量写入、`cognee.config` setter、Embedding 网关补丁和并发补丁收敛为幂等的 `apply_cognee_runtime(snapshot)`。为已知的 Cognee/LiteLLM 客户端单例提供显式 reset hook；补丁安装保持幂等，不因每次重载重复包裹函数。

`init_cognee()` 保留为兼容入口，但内部改为获取当前快照租约或确保协调器已应用，不再抛出“必须重启”错误。旧的 `_active_gateway_fingerprint` 和 `cognee_gateway_restart_required()` 逐步替换为协调器状态查询。

### 5. 工作进程在任务入口惰性收敛

设置保存接口只负责持久化、递增 `runtimeRevision`、清理本进程普通 Agent 缓存并唤醒本进程协调器，不通过内存事件假设所有工作进程都能收到通知。

每个 API/任务工作进程在获取 Cognee 租约时读取共享版本，因此多进程、滚动部署和漏掉通知的进程仍会自行收敛。为避免每个内部模型请求访问 SQLite，版本检查仅发生在任务/公开 Cognee 操作入口；一个租约内使用固定快照。

### 6. 分离运行时热重载与知识库向量兼容性

每个项目知识库保存 `embedding_signature`，由规范化模型 ID、实际向量维度和影响向量语义的参数组成。Base URL 和 API Key 不进入该签名；仅更换凭证不要求重建知识库。

- 新建或重建知识库时写入当前签名。
- 查询或增量写入已有知识库前比较签名。
- 签名不同则返回 `knowledge_embedding_rebuild_required`，包含旧/新模型和维度的非敏感摘要。
- 明确的全量重建操作允许使用新签名，并在成功完成后原子替换签名。

即使两个模型维度相同，模型 ID 变化也要求重建，因为向量空间并不兼容。

### 7. 运行状态以“期望版本/活动版本”表达

模型网关配置状态增加：`desiredRevision`、`activeRevision`、`runtimeState`、`activeLeaseCount`、`lastAppliedAt` 和脱敏的 `lastReloadError`。`restartRequiredComponents` 在兼容期继续返回，但 Cognee 热重载开启后不得再加入 `cognee`。

状态只描述当前响应进程。多进程部署不伪造集群级全部已生效结论；任务入口的一致性检查才是最终保障。前端在 `draining/applying` 时显示“将在当前知识库任务完成后生效”，在 `failed` 时展示可操作错误。

### 8. 超时不强杀旧任务

排空等待不主动取消或杀死正在执行的知识库任务。等待中的新任务使用可配置超时，超时后返回 `model_runtime_reload_wait_timeout`，用户可重试。管理员仍可通过现有任务取消能力终止长时间任务，租约在取消路径的 `finally` 中释放。

## Risks / Trade-offs

- [长任务导致新配置迟迟不能生效] → 展示活跃租约和排空状态，为等待任务设置超时，并允许用户取消旧任务。
- [遗漏某个 Cognee 调用入口导致切换期间串线] → 所有公开 Store 操作统一经过一个装饰器/上下文管理器，并增加并发回归测试和无租约调用断言。
- [第三方 Cognee 缓存无法完全重置] → 将缓存 reset hook 集中并做版本兼容测试；若不支持安全重载，应用失败而不是静默继续。
- [配置应用失败后服务状态复杂] → 保留旧值用于回滚进程状态，但阻止新租约，状态接口输出脱敏错误并等待下一版本修复。
- [Embedding 变更造成历史向量错误结果] → 使用项目级签名硬性阻断读取和增量写入，要求显式全量重建。
- [多进程状态展示不一致] → 每个任务入口强制检查共享版本；状态 API 明确是本进程观测值，不宣称集群全局完成。
- [频繁保存造成抖动] → 排空期间合并到最新快照，有效指纹未变化时只推进版本而不重配。

## Migration Plan

1. 引入快照、协调器和只读状态，暂时保留现有重启保护作为开关回退路径。
2. 将 Cognee 配置应用逻辑迁入幂等适配层，并增加环境变量、配置对象与缓存重置测试。
3. 把导入、建图、索引、搜索和 Agent 检索入口纳入任务级租约。
4. 增加项目 Embedding 签名；没有签名的旧知识库首次读取时按当前已知配置迁移，无法可靠判断时要求重建。
5. 更新保存接口和设置页状态，启用热重载并停止写入 `restartRequiredComponents=["cognee"]`。
6. 先在单工作进程验证，再验证多进程下各进程按任务入口惰性收敛。
7. 稳定后删除 `_active_gateway_fingerprint` 的重启分支和旧提示文案。

回滚时关闭热重载开关，恢复原“配置变化后要求重启”保护；不回滚 `runtimeRevision` 或删除项目 Embedding 签名。

## Open Questions

- 当前锁定的 Cognee 版本中，除 LiteLLM 路由外还有哪些 LLM 客户端单例需要显式 reset hook？实施第一阶段通过对象检查和集成测试确认。
- 生产部署是否会使用多个独立任务进程且共享同一个 `settings.db`？若未来改为远程数据库，版本读取接口保持不变，但状态聚合可另行增加。
